# Research Desk 사용·계정 구성 가이드

## 계정 연결과 역할

관리자가 ADMIN_GUIDE대로 앱·Keycloak을 구성한 뒤 앱의 로그인을 누른다. Keycloak 로그인 화면에 Google/네이버 버튼이 나타나려면 해당 IdP를 Terraform에서 활성화해야 한다. 최초 소셜 로그인 후 역할이 없으면 role_required가 나온다. 관리자가 ai-signal realm의 사용자에게 page-manager 클라이언트 역할을 부여한 뒤 다시 로그인한다.

로그인할 수 있다는 사실과 편집 권한은 별개다. 계정 이메일이 같더라도 다른 제공자의 계정을 자동 병합하지 않는다. 최초 연결 시 기존 계정 확인 절차를 따른다. 네이버 프로필 항목은 동의 여부에 따라 없을 수 있으며 앱은 Keycloak sub로 식별한다.

## 나만의 기술 브리핑 만들기

1. editor/admin으로 로그인한다.
2. ‘새 브리핑’에서 제목을 적는다. 예: ‘이번 주 IAM 설계 실험’.
3. ‘최근 뉴스 불러오기’를 누르고 관심 기사 옆 ‘담기’를 선택한다. 외부 링크를 직접 추가해도 된다.
4. 본문에 핵심 내용, 내 환경에 적용할 점, 실험할 내용, 확인 결과를 적는다.
5. 태그를 쉼표로 구분하고 학습 단계 ‘읽기’를 선택한다.
6. 개인 작업 중에는 ‘개인 초안’, 팀원에게 보여줄 때는 ‘역할이 있는 팀원에게 공유’를 선택한다.
7. 저장 후 목록에서 다시 열어 내용과 링크를 확인한다. 단계가 바뀌면 ‘실습’, ‘정리’로 변경한다.

‘공유’는 인터넷 공개가 아니다. viewer/editor/admin 역할이 있는 앱 사용자에게만 보인다. 관리자에게는 개인 초안도 보인다. 본문은 일반 텍스트이며 Markdown 문법을 입력해도 리치 텍스트 렌더링하지 않는다.

## 편집과 세션

- 앱 세션은 최대 5분이다. 만료 전에 저장하고 긴 편집은 텍스트를 별도로 복사해 둔다. 자동 저장·브라우저 영속 초안 기능은 아직 없다.
- 동시 수정 오류가 나면 현재 입력을 복사하고 목록을 새로고침한 다음 최신 페이지와 병합한다.
- editor는 다른 사람의 공유 페이지를 읽을 수 있지만 수정할 수 없다.
- 삭제는 admin에게만 보이며 실제 삭제 전 확인창이 뜬다. 삭제 휴지통은 아직 없다.
- ‘앱 로그아웃’은 이 앱 세션만 끝낸다. Keycloak과 Google/네이버 로그인 상태까지 모두 종료하지는 않는다.
- 화면 통계와 검색은 불러온 최근 100개 기준이다.

## 확인할 문제

| 증상 | 확인 |
|---|---|
| role_required | page-manager client role 할당 후 재로그인 |
| invalid_callback | 오래된 로그인 탭 종료 후 새 로그인; 쿠키 차단 여부 |
| login_failed/invalid_identity | client secret, issuer, clock, role mapper 설정 |
| service_unavailable | EC2·DNS·TLS·D1 migration 상태 |
| csrf_rejected | APP_ORIGIN과 실제 접속 origin 일치 여부 |
| 네이버에서 redirect 오류 | 네이버 callback은 앱 URL이 아니라 broker/naver/endpoint |
| 저장 충돌 | 다른 탭 변경 또는 소유권 확인 |

원본·토큰·비밀번호가 포함된 URL이나 로그를 공개해서 공유하지 않는다. 오류 코드와 비밀 제거한 설정 이름으로 문의한다.
